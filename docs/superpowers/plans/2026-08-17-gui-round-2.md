# GUI Round 2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move `signal-desktop` and `bitwarden` from apt to Nix, building the first deliberate exemption for `wrappedGuiApps` and correcting the two `mimeapps.list` handlers that name Signal's Debian id.

**Architecture:** The GL verdict comes first, before any code, because it can veto the whole spec and costs one command. Then two independent code tasks — the exemption in `home/gui-apps.nix`, the mimeapps hook in `home/apps.nix` — then a user gate that switches and removes, then close-out.

**Tech Stack:** Nix flakes, standalone Home Manager (`release-26.05`), `dpkg-query`, `apt-get -s`, `sed`.

**Spec:** `docs/superpowers/specs/2026-08-17-gui-round-2-design.md`

**One deliberate departure from the spec.** The spec places the GL gate before the *apt removal*. This plan places it before *everything*, as Task 1. Both packages can be run straight from their store paths without installing anything, exactly as spec 10 ran `$SH/bin/seahorse`, so there is no reason to design an exemption for an application that cannot draw. If the gate fails, Tasks 2-5 change shape or do not happen.

## Global Constraints

- Every `nix` and `home-manager` invocation wrapped: `sg nix-users -c '...'`.
- **No agent runs** `home-manager switch`, the activation script without `DRY_RUN=1`, any mutating `apt`/`apt-get` (without `-s`)/`dpkg`/`apt-mark` command, `systemctl` with `start`/`stop`/`restart`/`enable`/`disable`/`daemon-reload`, `reboot`, or `hyprctl keyword`/`dispatch`.
- **No agent modifies `~/.config/mimeapps.list`.** Task 3 proves its hook against a *copy*. The live file is written only by the user's own switch, in Task 4.
- Package presence via `dpkg-query -W -f='${db:Status-Abbrev} ${Package} ${Version}\n'`, never a bare version query.
- Never read a package version from `nixpkgs#<pkg>`; only `.#homeConfigurations."isutton@suffer".pkgs.<pkg>.version`.
- The nixpkgs attribute is **`bitwarden-desktop`**. Plain `pkgs.bitwarden` throws `'bitwarden' has been renamed to/replaced by 'bitwarden-desktop'`.
- No path under the plan's git-ignored scratch directory in any committed file.
- **A Nix builder and the Home Manager activation script both run with `set -e` and `pipefail`, but a body handed to a child `sh -c` inherits neither.** Check `$-` in the shell that will really run the line before deciding what protects it. `grep -c` prints 0 and exits 1 at zero matches.
- **Prove every guard can fail, by mutation, with the mutation confirmed by a count before the build runs.** Three checks in this project have passed while the property they stood for was false.
- Enumerate by syntax; do not trust a list of names, including this plan's.

- [ ] **Step 1: Add the exemption table and both packages**

In `home/gui-apps.nix`'s `let`, before `wrappedGuiApps`:

```nix
  # Packages that legitimately need no GSettings wrapper, each with the reason.
  #
  # Explicit, and NOT derived. The derived rule -- "ships no schemas of its own,
  # therefore nothing to wrap" -- is what this guard shipped with in spec 10, and
  # gammastep disproved it in this very file: it ships no schemas of its own yet
  # both its binaries are wrapped, because the schemas that matter come from its
  # dependencies. Deriving again would be the same mistake with a new rule.
  #
  # Keyed by `lib.getName`, which is the pname, so the key survives a version
  # bump. Checked in both directions -- see the staleness branch in the guard.
  wrapExemptions = {
    signal-desktop    = "Electron. Ships no GSettings schema, no wrapped binary, and no GLib settings backend to find one with.";
    bitwarden-desktop = "Electron. Same shape as signal-desktop.";
  };
```

and extend the package list:

```nix
  guiPackages = [ pkgs.seahorse pkgs.gammastep pkgs.signal-desktop pkgs.bitwarden-desktop ];
```

- [ ] **Step 2: Replace the guard body with the two-way check**

```nix
  wrappedGuiApps = pkgs.runCommand "gui-apps-schema-wrapped" { } ''
    fail=0
    exempt="${lib.concatStringsSep " " (lib.attrNames wrapExemptions)}"

    check() {
      name="$1"; pkg="$2"
      wrapped="$(find "$pkg/bin" -maxdepth 1 -name '.*-wrapped' 2>/dev/null | wc -l)"

      is_exempt=0
      for e in $exempt; do
        if [ "$e" = "$name" ]; then is_exempt=1; fi
      done

      if [ "$is_exempt" -eq 1 ]; then
        # The staleness half. An exemption that has stopped being true is worse
        # than no exemption, because it goes on excusing a package that has
        # started needing the check. Upstream adding wrapGAppsHook must break
        # this build, not pass quietly.
        if [ "$wrapped" -gt 0 ]; then
          echo "$name is on wrapExemptions but ships $wrapped wrapped binary(ies)." >&2
          echo "  The exemption has gone stale: upstream now wraps this package," >&2
          echo "  so it should be checked like any other. Remove its entry from" >&2
          echo "  wrapExemptions in home/gui-apps.nix." >&2
          fail=1
          return 0
        fi
        echo "ok (exempt): $name" >&2
        return 0
      fi

      if [ "$wrapped" -eq 0 ]; then
        echo "$name ships no wrapped binary and is not exempt." >&2
        echo "  nixpkgs relocates GSettings schemas to share/gsettings-schemas/," >&2
        echo "  which GLib never searches; wrapGAppsHook is what puts them back on" >&2
        echo "  XDG_DATA_DIRS. Without a wrapper a GTK application aborts at" >&2
        echo "  startup with \"Settings schema ... is not installed\"." >&2
        echo "  If it genuinely needs none -- an Electron app, say -- add it to" >&2
        echo "  wrapExemptions in home/gui-apps.nix WITH ITS REASON." >&2
        fail=1
        return 0
      fi

      echo "ok ($wrapped wrapped): $name" >&2
    }

    ${lib.concatMapStringsSep "\n    "
        (p: ''check "${lib.getName p}" "${p}"'') guiPackages}

    [ "$fail" -eq 0 ] || exit 1
    # A directory, not `touch "$out"`: this output is reached from home.packages
    # through gui-apps-guard's symlink, and pkgs.buildEnv requires every package
    # it merges to resolve to a directory.
    mkdir -p "$out"
  '';
```

## Task 3: Signal's mimeapps handlers

**Files:** Modify `home/apps.nix`.

**Interfaces:**
- Consumes: nothing from Task 2.
- Produces: the hook whose effect Task 4's switch applies to the live file.

- [ ] **Step 1: Add the hook**

```nix
  # Signal's .desktop id changes across the Debian/Nix boundary --
  # signal-desktop.desktop becomes signal.desktop -- and two handlers in
  # ~/.config/mimeapps.list name the old one. Migrating without this leaves
  # x-scheme-handler/sgnl and x-scheme-handler/signalcaptcha pointing at an id
  # that does not exist, silently.
  #
  # This writes a file the flake does not own, which is why it is narrow:
  # it rewrites only the exact token signal-desktop.desktop, only where that
  # token is a whole value, and it touches nothing else. mimeapps.list also
  # carries ids this flake will never own -- a dead
  # eu.calangotech.KBrowserSelector.desktop, and slack.desktop where flatpak
  # exports com.slack.Slack.desktop -- and those must survive untouched.
  #
  # Idempotent: the grep guard means a second run finds nothing and exits before
  # sed is invoked. Non-fatal for the same reason mimeappsIds is -- this is the
  # user's file, and a switch must not abort over it.
  config.home.activation.signalMimeappsId =
    lib.hm.dag.entryAfter [ "writeBoundary" ] ''
      run ${pkgs.bash}/bin/sh -c '
        list="$HOME/.config/mimeapps.list"
        [ -w "$list" ] || exit 0
        ${pkgs.gnugrep}/bin/grep -q "signal-desktop\.desktop" "$list" || exit 0
        ${pkgs.gnused}/bin/sed -i \
          "s/\(^\|[=;]\)signal-desktop\.desktop\($\|;\)/\1signal.desktop\2/g" \
          "$list"
        echo "mimeapps.list: signal-desktop.desktop -> signal.desktop" >&2
      ' || true
    '';
```

- [ ] **Step 2: Build and confirm the hook is emitted**

```bash
NEW=$(sg nix-users -c 'nix build --no-link --print-out-paths .#homeConfigurations."isutton@suffer".activationPackage' | tail -1)
grep -c 'signalMimeappsId' "$NEW/activate"
```

Expected: `1` or more.

- [ ] **Step 3: Prove the sed against a COPY, never the live file**

```bash
T="$(mktemp -d)"
cp ~/.config/mimeapps.list "$T/m"
md5sum "$T/m" > "$T/before"
sed -i 's/\(^\|[=;]\)signal-desktop\.desktop\($\|;\)/\1signal.desktop\2/g' "$T/m"
diff ~/.config/mimeapps.list "$T/m"
```

Expected: **exactly two changed lines**, both `signal-desktop.desktop` → `signal.desktop`. If `diff` shows anything else — a KBrowserSelector line, a slack line, a reordering — the regex is wrong.

- [ ] **Step 4: Prove idempotence**

```bash
md5sum "$T/m" > "$T/once"
sed -i 's/\(^\|[=;]\)signal-desktop\.desktop\($\|;\)/\1signal.desktop\2/g' "$T/m"
md5sum "$T/m" > "$T/twice"
diff "$T/once" "$T/twice" && echo "IDEMPOTENT"
rm -rf "$T"
```

Expected: `IDEMPOTENT`.

**Placeholder scan.** Every step carries its command or its Nix. Task 5's steps describe content rather than showing it, because that content is the outcome of Tasks 1-4 and inventing it now would be inventing results.

**Ordering.** Task 1 first because it can veto. Tasks 2 and 3 are independent and touch different files. Task 4 needs both. Task 5 needs Task 4's results.

**Task 2's Nix was built and both its failure branches proven before this plan was committed**, then reverted so Task 2 does the work as written.
