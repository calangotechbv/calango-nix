### Reading `hyprctl` from outside the session

`hyprctl` needs `HYPRLAND_INSTANCE_SIGNATURE`, and a shell that predates the
current login carries a stale one — the failure is
`Couldn't connect to /run/user/1000/hypr/<sig>/.socket.sock. (4)`, which looks
like a dead compositor rather than a stale variable. The live instance is the
newest entry under `/run/user/1000/hypr/`:

```sh
export HYPRLAND_INSTANCE_SIGNATURE=$(ls -t /run/user/1000/hypr/ | head -1)
```

The signature's prefix identifies the build: `a0136d8c…` is the Nix 0.55.4,
`39d7e209…` is apt's 0.55.2. Useful for telling at a glance which compositor a
socket belongs to.

## The two real defects

Both were invisible to static review and only appeared on a real launch.

### 1. A `qmldir` hid nine components

quickshell crash-looped, `status=255/EXCEPTION`, restart counter 10:

```
ERROR: Failed to load configuration
ERROR:   caused by @shell.qml[35:3]: Type ThemeSwitcher unavailable
ERROR:   caused by @theme-switcher/ThemeSwitcher.qml[69:5]: Scrim is not a type
```

`Paths.qml` is a `pragma Singleton`, and a QML singleton needs a `qmldir`
entry to be importable. But calango-desktop had **no** `qmldir` in `common/`,
so QML treated the directory as an implicit import in which every `.qml` is a
type. Adding a `qmldir` converts the directory to an explicit manifest, and
every type it does not list disappears — all nine of `AppLaunch`,
`BarSettings`, `CloseButton`, `Icon`, `Icons`, `PanelGroup`,
`ScreencastService`, `Screens` and `Scrim`.

The fix lists all ten, with the `singleton` keyword on exactly those files
carrying `pragma Singleton`.

Worth keeping: **adding a `qmldir` is not additive.** It changes resolution
for files it does not mention. Two reviews passed this diff, because in
isolation it is correct and nothing static reveals the interaction.

### 2. matugen's CLI had drifted, twice

`theme-switcher/wallpaper-theme/set.sh` could not generate a wallpaper theme.
Two separate causes, found in sequence:

- **`--prefer saturation` no longer exists.** matugen 4.0.0 answers
  `tip: a similar argument exists: '--prefix'`. Palette choice now lives in
  `-t/--type <scheme-*>`, defaulting to `scheme-tonal-spot`. calango-desktop
  was written against an older cargo-installed matugen.
- **matugen 4.x cannot pick a source colour without a controlling tty:**
  `Failed to get source color… IO error: not a terminal`. quickshell invokes
  `set.sh` from a systemd-managed `Process`, which never has one, so this was
  a production failure and not a testing artifact. Reproduced against a
  synthetic PNG, so it is not wallpaper-specific. `--source-color-index 0`
  fixes it.

`--prefer` was dropped without substituting a `--type`: `scheme-vibrant` is
the plausible successor, but choosing it would invent an aesthetic and
silently change the palette. The default is working and reversible — adding
`--type scheme-vibrant` is a one-line change if the old look is wanted back.

This is the first place Nix's *newer* package was a cost rather than a
benefit. `matugen` and `wallust` are cargo installs on Debian, and spec 2
counted that as work removed; the version jump brought CLI drift with it.

## The state contract

| Check | Result |
|---|---|
| theme change persists to `~/.local/state` | **passes** — see below |
| `~/.config/quickshell` stays absent | passes |
| `wallpaper-theme.json` generated by `set.sh` | passes, 398 bytes, in state |
| nothing written into the store | passes |

The persistence check proved itself without being induced.
`night-light-location.conf` was seeded at 05:28 and its mtime moved to 05:52
when the shell started — `locate.sh` rewrote it, through the rewritten path,
with the same value. A live write landing in the state directory.

Home Manager owns exactly two paths under `~/.local/state/quickshell`: `.keep`
and `theme-switcher/.keep`, both store symlinks forcing real parent
directories. Every other file there is a real, mutable file.

## The runtime closure

All fifteen packages resolve on the unit's `PATH`, and `python3` imports
`PIL` 12.3.0. Exercised for real: `matugen` 4.0.0, `wallust` 3.5.2, `jq`,
`sh`, `cat`, and `hyprctl`. Taken on trust from `command -v`, pending a
person driving the interface: `brightnessctl`, `cliphist`, `wl-copy`,
`swaybg` (though a `wallpaper` layer exists, so it ran), `gsettings`,
`notify-send`, `curl`, `systemctl`.

`libnotify` is in the closure but `notify-send` is never invoked —
quickshell implements its own DBus `org.freedesktop.Notifications` server.
One wrong row in spec 2's runtime-closure table.

## Closed open items

- **wallust does not need a writable `-d` directory.** `set.sh` passes it a
  store path; wallust read its config and templates from there and wrote only
  to the state directory. The spec listed this as untested.

## Partial features: two predictions were wrong

The spec predicted four features would arrive incomplete. Two behaved as
predicted; two did not, both because a directory the spec assumed absent
turned out to exist and be writable.

| Feature | Predicted | Observed |
|---|---|---|
| browser selector | writes state, no handler until spec 4 | as predicted — `.previous-browser` present, handler absent |
| night light | no schedule until spec 5 | as predicted — `night-light.service` inactive |
| theming beyond quickshell | `hypr/theme-borders.conf` would not exist | **wrong** — it exists, 113 bytes, written at 06:11 |
| bluetooth pairing | no agent until spec 5 | **wrong** — `bt-agent.service` reports active |

**`theme-borders.conf` is written, not skipped.** `~/.config/hypr` exists and
is writable because Home Manager puts `hypridle.conf` and `hyprland.conf`
there, so the theme switcher's out-of-scope write succeeds. The file lands
with real content; nothing reads it, because spec 1's minimal
`hyprland.conf` does not source it. quickshell also created an empty
`hyprlock.conf` in the same directory — worth knowing before spec 3 writes
its own.

So the boundary is not "the write fails" but "the write lands and is
ignored". Spec 3 will find these files already present.

**`bt-agent` and `nm-secret-agent` are orphans, not survivors.** Both report
`active`, but `FragmentPath=` is empty and both started at 04:22 — before
spec 1's `install.sh --uninstall`. They are processes from the pre-port
session still running under a user manager that outlived the logout, with no
unit file behind them. They will not come back after a reboot. They are also
calango-desktop code still executing out of the old checkout, which is worth
stopping deliberately rather than waiting for a reboot:

```sh
systemctl --user stop bt-agent.service nm-secret-agent.service
```

Left running here rather than stopped, because they handle bluetooth pairing
and network secrets in a live session.

## Surprises

The two defects share a shape worth naming: **both were correct in isolation
and wrong in context.** The `qmldir` was a valid file that changed the meaning
of files it did not mention; the matugen flags were valid for the version
calango-desktop was written against. Neither is the kind of error that review
of a diff can catch, and both took a real launch to surface — which is the
argument for the plan's insistence that `hyprctl layers`, not
`systemctl is-active`, is the test that counts.
